# Git view Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the agents column's Split view with a read-only Git view (changes and commits of the Files panel root's repository) whose file rows open unified-diff Open items.

**Architecture:** Rust runs read-only git through the Machine's `Transport` and returns typed, size-capped results (`src-tauri/src/git/`). The frontend adds a `"git"` sidebar view (`src/git/GitPanel.tsx`), a `"diff"` Open item kind, and a virtualized `DiffViewer` that highlights each hunk side with the existing lowlight helper.

**Tech Stack:** Tauri 2 (Rust, tokio, serde), React 19, zustand 5, @tanstack/react-virtual, lowlight, vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-16-git-view-design.md` (ADR: `docs/adr/0010-git-view-is-read-only.md`)

## Global Constraints

- Read-only: the only git subcommands any code may run are `rev-parse`, `status`, `log`, `diff`, `diff-tree` (ADR 0010).
- Every git invocation starts with the constant `git::GIT` = `git --no-optional-locks --no-pager -c core.quotepath=off -c color.ui=never`, spliced into scripts with `format!`; paths, shas and numbers reach the script only as positional arguments (`sh -c '<script>' sh <args…>`), never spliced.
- Scripts that `cd` into a folder use `cd "$1" 2>/dev/null || exit 97`; exit 97 maps to `AppError::new("not_found", format!("no such folder: {dir}"))`.
- A git failure maps to `AppError::new("git", <git's stderr trimmed, or "git exited with status N" when empty>)` through the one helper `git::failed(&ExecOutput) -> AppError`.
- A sha argument must pass `git::valid_sha` (`^[0-9a-f]{4,64}$`) before anything runs; otherwise `AppError::new("invalid", "not a commit id")`.
- Diff bodies are capped at `crate::files::MAX_TEXT_BYTES` (2 MB) on the Machine; the Git view lists at most `MAX_GIT_ENTRIES = 5000` entries.
- Serde field names stay snake_case and the TS types in `src/lib/types.ts` mirror them (`orig_path`, `old_no`, …), as `GitStatus` already does. Rust `Option` is TS `T | null`; Rust `char` is a one-character TS `string`.
- IPC wrappers in `src/lib/ipc.ts` pass camelCase argument names (`machineId`, `origPath`); Tauri maps them to the snake_case parameters.
- `repoKey(machineId, dir) = machineId + "|" + dir` (in `src/git/store.ts`). `useGit.repos` is keyed by the Files root (`repoKey(machine, root.path)`), because the repository is unknown before the first read. `logs`, `commitFiles`, `expanded`, `ticks` and `useGitRefresh` are keyed by the repository (`repoKey(machine, repo.root)`); GitPanel's ⟳ bumps that key and DiffViewer listens on `repoKey(machine, item.repo)`.
- Repository-relative paths (as git prints them) are called `path`; Files-root-relative paths are called `rel`. `src/git/paths.ts#relInRoot(prefix, path)` is the only conversion.
- Rust formatting: `rustfmt --edition 2021 <each .rs file you edited>`; never bare `cargo fmt`. `rustfmt` follows `mod` declarations, so run `git status` before `git add` and `git checkout --` any file you did not edit.
- Commands: Rust tests `cargo test --manifest-path src-tauri/Cargo.toml <filter>`; frontend tests `pnpm vitest run <file>`; types `pnpm typecheck`.
- UI copy is English, sentence case, exactly as written in this plan.
- CSS classes: Git view `git-panel`, `git-head`, `git-section`, `git-section-head`, `git-row`, `git-row-name`, `git-row-dir`, `git-letter git-letter-<X>` (X = M A D R C T U !), `git-commit`, `git-more`, `git-empty`; Diff viewer `diff-view`, `diff-head`, `diff-notice`, `diff-body`, `diff-row diff-<kind>` (kind = hunk context add del combined note), `diff-no` (with `data-n`), `diff-mark` (with `data-m`), `diff-code`.

## Review Focus

- A Files panel root that is a symlink or `~`-relative path, while git prints the real path: "Open file" must still resolve (Task 2 returns `prefix`, Task 8 converts with it, both tested).
- A repository without commits: status, log and Changes must work and show untracked files, not an error (Tasks 2, 3 tests).
- A merge commit: its files and diffs come from the first parent, never empty (Tasks 3, 5 tests).
- A diff over 2 MB over ssh: cut on the Machine, last partial line dropped, truncated notice shown (Tasks 4, 5, 13 tests).
- An Agent committing while the Git view is open: the list refreshes when the Agent leaves `working`, not only on ⟳ (Task 9 test).
